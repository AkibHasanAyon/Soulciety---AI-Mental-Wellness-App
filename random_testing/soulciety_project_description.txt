================================================================================
                        SOULCIETY — PROJECT DESCRIPTION
             A Spiritual Growth & Self-Transformation Mobile Platform
================================================================================

Project Name    : Soulciety
Platform        : Mobile Application (iOS & Android) with REST API Backend
Backend Stack   : Django 5.2, Django REST Framework, Celery, Redis, PostgreSQL
AI Engine       : Google Gemini (gemini-3-flash-preview, gemini-2.5-flash)
Cloud Services  : Cloudinary (Media Storage), Firebase (Push Notifications)
Deployment      : Docker / Docker Compose with Gunicorn, WhiteNoise
Domain          : soulciety.cloud


================================================================================
1. EXECUTIVE SUMMARY
================================================================================

Soulciety is a mobile-first spiritual growth and self-transformation platform
that combines AI-powered mentorship, reflective journaling, community
engagement, and curated spiritual content into a single unified experience. The
app serves as a personal consciousness coach, helping users permanently shift
their self-concept through the integrated teachings of Neville Goddard
(identity), Joe Dispenza (neuroscience), and Abraham Hicks (vibration) — without
ever naming these teachers directly.

At its core, Soulciety is built around the belief that "when self-concept
changes, reality follows." Every feature — from the AI chatbot to the community
prompts to the journaling system — is designed to facilitate this inner
transformation. The platform is not a generic self-help tool; it is a
carefully architected consciousness shift engine.

5.1  AUTHENTICATION & ACCOUNTS (accounts app)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The authentication system uses a custom user model (CustomUser) that replaces
the default Django username with email-based authentication. It supports
multiple registration pathways:

  REGISTRATION METHODS:
    • Email + Password Registration
      - User registers with email and password
      - 4-digit OTP sent to email for verification
      - Account activated only after OTP verification
      - JWT tokens (access + refresh) issued upon verification

    • Google OAuth (Social Auth)
      - Seamless Google Sign-In integration
      - Auto-creates user account and profile
      - Syncs Google profile picture (stored as social_profile_picture_url)
      - No password required (set as unusable)

    • Apple Sign-In (Social Auth)
      - Native Apple authentication support
      - Same flow as Google with Apple-specific handling
      - Privacy-focused — respects Apple's email relay

  SECURITY FEATURES:
    • JWT Authentication via SimpleJWT
      - Access token lifetime: 10 days
      - Refresh token lifetime: 30 days
    • OTP-based email verification (4-digit codes)
    • Forgot Password flow with OTP verification
    • Password reset with OTP validation
    • OTP resend capability
    • CSRF protection with trusted origins
    • CORS configuration

  API ENDPOINTS:
    POST /api/auth/register/          — Register new account
    POST /api/auth/login/             — Login with credentials
    POST /api/auth/verify-otp/        — Verify OTP code
    POST /api/auth/forgot-password/   — Request password reset OTP
    POST /api/auth/reset-password/    — Reset password with OTP
    POST /api/auth/resend-otp/        — Resend OTP code
    POST /api/auth/google/            — Google social authentication
    POST /api/auth/apple/             — Apple social authentication

5.2  AI CHAT SYSTEM — THE SOULCIETY MENTOR (chat app)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This is the crown jewel of Soulciety. The AI chat system provides users with a
deeply personalized, spiritually-grounded conversational mentor that remembers
them across sessions and evolves its understanding over time.

  THE AI PERSONA — "SOULCIETY":
    The AI is not a chatbot — it is a spiritual transformation mentor. Its
    personality is warm, direct, humble, and deeply rooted in the truth that
    consciousness creates reality. It speaks like a wise best friend over
    coffee — casual, real, passionate. It holds the user's vision even when
    they can't see it themselves.

  CONVERSATION MANAGEMENT:
    • Multi-conversation support — users can have multiple active conversations
    • Conversations are ordered by last updated timestamp
    • Soft-delete support (is_active flag)
    • Auto-generated conversation titles via Gemini AI
      - Triggered after 5 messages if title is still "New Conversation"
      - Generates 3-6 word descriptive titles using gemini-2.5-flash-lite

  AI RESPONSE GENERATION (Celery Task):
    The AI response is generated asynchronously via a Celery task to avoid
    blocking the API request. The flow is:

    1. User sends message → saved to database immediately
    2. API returns HTTP 202 ("Soulciety AI is reflecting on your words...")
    3. Celery task processes in background:
       a. Builds memory context from user's stored memories
       b. Retrieves last 10 messages for conversation history
       c. Constructs system prompt with AI persona + injected memory
       d. Calls Google Gemini (gemini-3-flash-preview) with full context
       e. Saves AI response to database
       f. Triggers memory extraction every 10 messages
    4. Client polls for the latest message via dedicated endpoint

  AI BEHAVIOR RULES (built into system prompt):
    Rule Priority (when instructions conflict):
      1. Safety rules override everything
      2. Emotional validation comes before coaching
      3. Conversation and listening before teaching
      4. Coaching practices only after user's situation is understood
      5. Spiritual reframes support, not dominate

    Conversation Flow:
      - Never rushes to coach
      - First exchanges focus on understanding
      - Guides through: validation → spiritual reframe → identity
        reinforcement → personalized practice → reflective question
      - One piece of value per response, one question, then waits

    Emotional Pacing:
      - When someone shares pain — entire response is validation
      - No teaching, no reframes, no practices during pain
      - After 2-4 exchanges of validation, gradually introduces insight

    Crisis Safety Protocol:
      - Suicidal thoughts: compassionate response + grounding exercise
      - Does NOT provide crisis hotline AND exercise in same message
      - If no improvement: provides 988 hotline
      - Post-crisis: supportive listening, no spiritual coaching

    Voice:
      - Casual American English with contractions
      - Short conversational responses, not lectures
      - Never says: "Hello dear", "Certainly!", "As an AI", "Just stay positive"

  RATE LIMITING:
    • 30 AI messages per day per user
    • Rate limit checked via django-ratelimit with Redis backend
    • Custom rate limit key based on authenticated user ID

  PAGINATION:
    • Message history paginated (20 messages per page, max 50)
    • Supports page_size query parameter

  API ENDPOINTS:
    GET  /api/chat/conversations/           — List user's conversations
    POST /api/chat/conversations/           — Create new conversation
    GET  /api/chat/conversations/<id>/      — Get conversation details
    DELETE /api/chat/conversations/<id>/    — Delete conversation
    GET  /api/chat/conversations/<id>/messages/  — Get messages (paginated)
    POST /api/chat/conversations/<id>/messages/  — Send message to AI
    GET  /api/chat/conversations/<id>/latest/    — Get latest message (polling)

5.3  AI MEMORY SYSTEM (memory app)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Memory System is what transforms Soulciety from a stateless chatbot into a
deeply personal companion that knows and remembers each user over time. It is a
three-tier memory architecture:

  TIER 1 — STRUCTURED MEMORIES (UserMemory model):
    Stores extracted personal facts organized by category:
      • Identity     — name, gender, age, location, preferences
      • Family       — relationship status, children, partner details
      • Career       — job title, business, financial situation
      • Spiritual    — beliefs, manifestation goals, life vision
      • Emotional    — recurring struggles, triggers, coping mechanisms
      • Exercises    — practiced techniques, feedback, streaks
      • Patterns     — communication style, breakthroughs, recurring topics

    Each memory has:
      - key (e.g., "children") and value (e.g., "2 kids, ages 5 and 8")
      - Confidence score (0.0–1.0)
      - Source conversation reference
      - Soft-delete (is_active) for outdated facts
      - Unique together constraint: (user, category, key)

  TIER 2 — CONVERSATION SUMMARIES (ConversationSummary model):
    LLM-generated summaries of conversations that include:
      - Summary text capturing key points from user's perspective
      - Key topics as JSON array (e.g., ["startup stress", "self-worth"])
      - Dominant emotional state detected
      - Message count at time of summary generation

  TIER 3 — SEMANTIC VECTOR SEARCH (ChromaDB + Gemini Embeddings):
    Uses ChromaDB (a vector database) for semantic similarity search:
      - Each user gets their own ChromaDB collection
      - Memories embedded using Google Gemini text-embedding-004 model
      - At chat time, the current message is embedded and searched against
        stored memories to surface contextually relevant past insights
      - Distance threshold filtering (< 1.5) for relevance quality

  MEMORY EXTRACTION PIPELINE (Celery Task):
    Triggered automatically every 10 new messages in a conversation:
    1. Collects all conversation messages
    2. Gathers existing user memories to avoid duplicates
    3. Calls Gemini (gemini-3-flash-preview) with extraction system prompt
    4. Receives structured JSON with facts, summary, emotional state, topics
    5. Upserts facts into UserMemory (updates existing, creates new)
    6. Stores/updates ConversationSummary
    7. Stores memory embeddings in ChromaDB for future semantic search
    8. Logs extraction run in MemoryExtractionLog to prevent reprocessing

  MEMORY CONTEXT INJECTION:
    At chat time, the context_builder.py assembles a memory block:
      Section 1: Structured facts ("What you know about this person")
      Section 2: Recent conversation summaries (last 3)
      Section 3: Semantically relevant past insights (vector search, top 3)
    This block is appended to the system prompt with instructions to use
    the information naturally — never robotically or with "according to records."

5.4  REFLECTIVE JOURNALING (journal app)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The journaling system allows users to write personal reflections and receive
AI-generated spiritual insights on each entry.

  JOURNAL ENTRIES:
    • Free-form text content with optional mood tagging
    • Mood options: 😊 Happy, 😨 Fear, 😔 Sad, 😠 Angry, 🤢 Sick
    • Tagging support (comma-separated tags)
    • Privacy flag (is_private, default True)
    • Archive/unarchive functionality for organizing entries

  AI INSIGHT GENERATION (Celery Task):
    When a journal entry is created or its content is updated:
    1. A placeholder is shown: "✨ AI Insight: Reflecting on your thoughts..."
    2. Celery task calls Gemini (gemini-2.5-flash) to generate:
       - A 3-sentence poetic, healing spiritual reflection
       - A notification title (max 5 words with emoji)
       - A one-sentence notification teaser
    3. Response parsed as JSON with fallback to cleaned raw text
    4. Insight saved to journal entry (ai_insight field)
    5. Push notification sent with the insight teaser

  RATE LIMITING:
    • Users can create up to 3 journal entries per day
    • Enforced via django-ratelimit

  ARCHIVE SYSTEM:
    • Toggle archive status on any entry
    • Archived entries hidden from main feed
    • Separate endpoint to view archived entries

  API ENDPOINTS:
    GET  /api/journal/entries/               — List journal entries (non-archived)
    POST /api/journal/entries/               — Create new entry (triggers AI)
    GET  /api/journal/entries/<id>/          — Get single entry
    PUT  /api/journal/entries/<id>/          — Update entry (re-triggers AI if content changes)
    DELETE /api/journal/entries/<id>/        — Delete entry
    POST /api/journal/entries/<id>/archive/  — Toggle archive status
    GET  /api/journal/archived/             — List archived entries

A full-featured social community platform for spiritual growth, where users can
share thoughts, interact with each other, and engage with AI-generated daily
prompts.

  COMMUNITY POSTS:
    • Text-based posts with optional image upload (via Cloudinary)
    • Image cleanup on post deletion (Cloudinary asset destroyed)
    • Likes count and comments count (denormalized for performance)
    • Soft-delete support (is_active flag)
    • Timeline feed with tab filtering:
      - "all"       — All active posts
      - "following"  — Posts from followed users only
      - "my"         — Current user's posts only

  LIKE SYSTEM:
    • Toggle-based like/unlike functionality
    • Atomic increment/decrement of likes_count using F() expressions
    • Push notification sent to post author when liked
    • Unique constraint prevents double-likes

  COMMENT SYSTEM:
    • Thread-based comments on posts
    • Both comment author and post author can delete comments
    • Atomic comments_count tracking
    • Push notification to post author on new comments

  FOLLOW SYSTEM:
    • Toggle follow/unfollow functionality
    • Self-follow prevention
    • Push notification to followed user
    • Following users list endpoint

  POST REPORTING:
    • Users can report posts with a reason
    • Reports stored with reference to original post
    • Post reference preserved even if post is soft-deleted (SET_NULL)

  AI-POWERED DAILY PROMPTS (Celery Beat — 9 AM New York):
    The crown feature of the community. Every day at 9 AM (New York time),
    a Celery Beat scheduled task:
    1. Gets or creates a system user (soulciety-ai@system.local)
    2. Gathers the last 7 AI-generated prompts to avoid repetition
    3. Calls Gemini (gemini-2.5-flash) with a detailed creative prompt
    4. Generates a unique, engaging community conversation prompt
    5. Posts it as a CommunityPost from the system user
    6. Notifies all active users via push notification

    The prompts follow diverse formats:
      • One-Liner Gut Punch — short, piercing questions
      • Reflection Setup — scene + question
      • Multi-Layer Prompt — emotional momentum building
      • The Challenge — dare the community to act
      • Pattern Interrupt — counterintuitive openers

    Topics rotate across: breaking cycles, rewriting beliefs, highest self,
    healing, gratitude, facing fears, manifesting, relationships as mirrors,
    abundance mindset, present moment peace, and community support.

    Fallback prompts hardcoded in case Gemini is unavailable.

  DAILY PROMPT MODEL (DailyPrompt):
    • Curated prompt bank with categories:
      Self Reflection, Growth, Healing, Mindset, Gratitude, Vision
    • Usage tracking (times_used, last_used_at)
    • Least-recently-used ordering for fair rotation

  PRODUCT SHOWCASE:

  DAILY INSPIRATION REMINDERS (Celery Beat — 8 AM daily):

7. BACKGROUND TASK SYSTEM (Celery + Redis)
================================================================================

Soulciety relies heavily on asynchronous processing:

  CELERY WORKERS:
    • AI chat response generation
    • Memory extraction and vector storage
    • Journal insight generation
    • Conversation title generation
    • Video metadata update
    • Push notification delivery (bulk and individual)
    • Product notification dispatch

  CELERY BEAT SCHEDULED TASKS:
    • send-morning-reminders — 8:00 AM daily (app_home.tasks)
    • post-daily-community-prompt — 5:00 AM UTC / 9 AM New York (community.tasks)

  RESILIENCE FEATURES:
    • Max retries configured per task (2-3 retries)
    • Exponential backoff with configurable delays
    • Graceful fallback responses when AI fails
    • Task results stored in Django DB via django-celery-results
    • transaction.on_commit() ensures tasks queue only after DB commits
    • Non-fatal error handling for optional features (memory, notifications)
